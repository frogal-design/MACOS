## 2026-07-28 - [Supply Chain Surface Reduction & Direct Dependency Hardening]
**Vulnerability:** Exposure of unused backend/node packages (`express`, `@types/express`, `dotenv`, `@google/genai`) in a client-side frontend-only build, expanding the supply chain attack surface, and a high-severity CSRF vulnerability in older `react-router-dom` versions, plus environment variable exposure via Vite's global define block in `vite.config.ts`.
**Learning:** React applications built with Vite are fully static clients. Retaining backend dependencies like `express` or `dotenv` introduces unnecessary security risks and potential supply chain vulnerabilities. Additionally, configuring a global define mapping like `process.env.GEMINI_API_KEY` in `vite.config.ts` injects secrets directly into public production assets, leading to API key leakage.
**Prevention:** Remove unused dependencies immediately after architectural refinement. Categorize development-only tools like `vite` as `devDependencies`. Secure essential runtime packages by upgrading them (e.g., `react-router-dom` to `^7.18.1` and `vite` to `^6.4.3`). Avoid global define blocks that bundle sensitive keys; instead, leverage `import.meta.env` for environment variables and ensure secrets are only handled by secure server-side proxies or backend services.
