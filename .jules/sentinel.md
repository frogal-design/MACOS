## 2026-07-29 - [Supply Chain Surface Reduction & Direct Dependency Hardening]
**Vulnerability:** Redundant inclusion of developer-only environment utility configurations (`dotenv`, `process.env.GEMINI_API_KEY` global define block) and unused backend artifacts (`express`, `@google/genai`) within a pure, static client-side single page application (SPA). This increases the attack surface via unnecessary transitive dependencies (supply chain vulnerability risks) and introduces a high risk of baking development secrets directly into compiled production client JavaScript bundles.
**Learning:** Merging older branches or pulling in boilerplate configurations can re-introduce legacy "global define" blocks and backend packages that are completely unused in the frontend codebase. In Vite-based applications, the `dotenv` package is redundant since Vite natively manages environment variable loading, and exposing sensitive API keys globally via Vite's `define` compiles those values directly into client-accessible assets.
**Prevention:**
1. Maintain a strict division between frontend-only dependencies and dev/build tools (e.g., ensure `vite` is strictly categorized as a `devDependency`).
2. Never inject environment variables globally via `vite.config.ts` unless they are explicitly meant for client-side consumption (and always prefix public environment variables with `VITE_` per Vite standards).
3. Periodically audit the dependency manifest (`package.json`) and run dead-dependency checks to purge unused backend dependencies to minimize the supply chain attack surface.
