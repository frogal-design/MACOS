## 2026-08-03 - [Supply Chain Surface Reduction & Direct Dependency Hardening]
**Vulnerability:** The configuration injected a sensitive `GEMINI_API_KEY` into the client-side bundle globally via Vite's `define` property, and the project had outdated dependencies (e.g. `react-router-dom` and `vite` versions) susceptible to CSRF, DoS, and arbitrary file read, along with unused backend dependencies.
**Learning:** Hardcoding or globally injecting environment secrets via a bundler's global definition block runs a high risk of leaking keys in the production static asset chunks. Unused server-oriented dependencies like `express` or utility libraries like `dotenv` expand the supply chain attack surface in a pure SPA environment.
**Prevention:** Avoid injecting server-side secrets via global definitions (`define` in config); instead, use environment variable files and only reference them where needed via standard `import.meta.env`. Standardize dependency updates and aggressively remove unused artifacts (e.g., `express`, `dotenv`, `@google/genai`) to minimize the supply-chain risk profile.
